# Frontend Design

## Workflow
1. Clarify the audience, primary action, content, brand constraints, framework, and acceptance criteria.
2. Choose a visual direction: typography, color roles, density, imagery, and interaction character.
3. Establish hierarchy so the primary task is clear.
4. Build reusable primitives for navigation, buttons, fields, panels, and feedback.
5. Include loading, empty, error, disabled, success, and validation states when relevant.
6. Preserve task flow across viewport sizes.
7. Use interaction and animation to clarify feedback, not distract from tasks.
8. Check semantic HTML, visible focus, contrast, keyboard support, and reduced-motion preferences.
9. Polish spacing, type rhythm, borders, image crop, and component states.
10. Run available checks and compare the rendered result against acceptance criteria.

## Review questions
- Can a new user identify the page purpose and primary action quickly?
- Is the hierarchy clear at a glance?
- Are related controls grouped and labeled consistently?
- Do interactive states remain clear without color alone?
- Does the layout work with long, missing, or realistic content?
- Does the visual direction fit the product and audience?
- Are dependencies and custom effects justified?

## Guidelines
- Avoid defaulting every project to the same gradient, glass effect, or card grid.
- Prefer a few strong visual decisions over decorative overload.
- Do not sacrifice readability or keyboard usability for novelty.
- Follow existing project conventions unless a change is justified.
