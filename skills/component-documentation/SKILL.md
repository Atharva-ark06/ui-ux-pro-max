# Component Documentation
For each component, document:
- Purpose and when not to use it.
- Required and optional props, defaults, and constraints.
- Visual and interaction states.
- Keyboard behavior and accessible naming expectations.
- Responsive behavior and content limits.
- A minimal example and one realistic edge case.
- Known limitations and migration notes for breaking changes.
Keep examples aligned with the current implementation. Prefer demonstrated behavior over untested claims.
