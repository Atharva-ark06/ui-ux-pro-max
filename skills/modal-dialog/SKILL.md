# Dialog and Modal Guidance
1. Use a dialog only when the task benefits from keeping the current context in place.
2. Give it a descriptive title and concise explanation.
3. Move focus into the dialog when opened and return focus to the trigger when closed.
4. Keep keyboard navigation within a truly modal dialog and support expected dismissal behavior.
5. Ensure important actions remain visible on short screens and zoomed layouts.
6. Use explicit labels for destructive actions; do not rely on color alone.
7. Prevent accidental loss of unsaved work and explain consequences.
8. Test keyboard, screen reader, narrow viewport, and nested overlay behavior.
