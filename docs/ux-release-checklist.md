# UX Release Readiness Checklist

## Task completion
- [ ] The primary user task works from start to finish.
- [ ] Success, loading, empty, validation, and failure states are covered.
- [ ] Destructive or irreversible actions explain their consequences.

## Accessibility and responsive behavior
- [ ] Keyboard navigation and visible focus are checked.
- [ ] Labels, error descriptions, and status messages are reviewed.
- [ ] Supported viewport sizes, zoom, and long content are checked.
- [ ] Reduced-motion behavior is respected.

## Content and trust
- [ ] Instructions and calls to action describe the result accurately.
- [ ] Privacy, permission, and data-retention claims are verified.
- [ ] No placeholder copy, broken links, or misleading metrics remain.

## Release evidence
- [ ] Relevant tests, lint, and build checks are recorded.
- [ ] Manual checks identify browser, viewport, and test account/data.
- [ ] Known issues include impact, workaround, and owner.
- [ ] Follow-up work is prioritized and visible to the team.

A checklist is not proof by itself: attach results for high-risk flows and explicitly note checks that could not be completed.
