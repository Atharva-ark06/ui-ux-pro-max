# Form Usability Review

## Before entry
- [ ] The purpose of the form and any prerequisites are clear.
- [ ] Required fields are identified before submission.
- [ ] Labels remain visible while users type.
- [ ] Input formats and examples are shown where ambiguity is likely.

## During entry
- [ ] Input types and autocomplete support the task.
- [ ] Related fields are grouped in a logical order.
- [ ] Validation timing avoids interrupting users unnecessarily.
- [ ] Errors explain how to fix the issue and preserve valid input.

## Submission and recovery
- [ ] Submission status is visible and duplicate actions are prevented where needed.
- [ ] Success confirms what happened and explains the next step.
- [ ] Server-side failures are distinguishable from field validation errors.
- [ ] Keyboard and screen-reader users can identify and reach invalid fields.

Test with realistic, incomplete, invalid, and boundary-value inputs. Do not rely on placeholder text as the only label.
