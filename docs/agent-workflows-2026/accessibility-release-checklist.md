# Frontend Accessibility Release Checklist

Use automated checks alongside manual testing; a clean scan does not prove a UI is fully accessible.

## Structure and labels

- [ ] Use semantic landmarks and logical headings.
- [ ] Use buttons for actions and links for navigation.
- [ ] Provide programmatic labels for form controls.
- [ ] Associate errors and help text with their controls.
- [ ] Give informative images meaningful alternative text.

## Keyboard and focus

- [ ] Interactive controls are keyboard reachable.
- [ ] Focus order is logical and visible.
- [ ] Dialogs manage and restore focus.
- [ ] No keyboard traps exist.

## Visual and dynamic states

- [ ] Text and essential controls have sufficient contrast.
- [ ] Color is not the only carrier of information.
- [ ] Zoom and reflow remain usable.
- [ ] Reduced-motion preferences are respected.
- [ ] Loading, error, empty, and success states are communicated.

Reference: https://www.w3.org/WAI/standards-guidelines/wcag/
