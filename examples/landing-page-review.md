# Example: Landing Page UX Review

This is an illustrative template. Replace these examples with observations from the actual page being reviewed; they are not claims about a specific product.

## Review context
- **Audience:** First-time visitors evaluating a product.
- **Primary task:** Understand the offer and start a trial or request a demo.
- **Devices:** Mobile and desktop.
- **Evidence:** Record whether the review used screenshots, a live interface, or source code.

## Illustrative findings

### High — Primary action competes with secondary actions
**Observation:** Several buttons have similar visual emphasis in the first viewport.

**Impact:** Visitors may be unsure which action is recommended.

**Recommendation:** Select one primary action and reduce the visual emphasis of secondary actions.

**Verification:** Ask a first-time visitor what they would do next after a brief glance; compare before and after.

### Medium — Benefits are expressed only as feature labels
**Observation:** The page lists technical terms without explaining user outcomes.

**Impact:** Visitors must infer why the features matter.

**Recommendation:** Pair important features with concise benefits and supporting evidence.

**Verification:** Check whether each section explains what users gain and why the claim is credible.

### Medium — Form errors are not tied to fields
**Observation:** A validation message appears at the top without identifying the invalid field.

**Impact:** Users must search the form to recover.

**Recommendation:** Associate the error with the control, provide a persistent label, and guide focus after failed submission.

**Verification:** Submit invalid data using only the keyboard and confirm the error is easy to locate and understand.
